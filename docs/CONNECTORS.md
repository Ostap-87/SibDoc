# Коннекторы и уведомления

Коннектор забирает данные из внешней системы и кладёт их в слоты (`wide_table`,
`purchase`, `ru_dt`, `cn_dec`, …). Уведомления отправляют итоги прогона и ошибки
коннекторов в рабочие чаты. Всё настраивается в `config/system.yaml`
(блоки `connectors:` и `notifications:`) и **по умолчанию выключено** (`enabled: false`).

## Что есть

| Очередь | Тип | Система | Что даёт |
|---|---|---|---|
| первая (работает) | `imap` | Почта брокеров | вложения Excel / CSV / XML / PDF / ZIP из писем (китайские имена файлов, повторно не забирает) |
| первая | `folder` | Папка на сервере | файлы китайского и российского брокера, выгрузки FineBI |
| первая | `sftp` | SFTP брокера / корпоративный | то же по SFTP; незнакомый сервер отклоняется (known_hosts или отпечаток ключа) |
| первая | `rest` | Любой REST/JSON API | записи -> CSV в слот; авторизация basic / bearer / ключ в заголовке; постраничная выдача |
| первая | `database` | БД FineBI и др. (SQLAlchemy) | SQL-запрос на слот |
| первая | `sap_odata` | SAP S/4HANA | OData v2 и v4 |
| вторая (задел) | `onec_odata` | 1С (стандартный OData) | заработает после публикации базы и выдачи пользователя |
| вторая | `etran` | ЭТРАН (РЖД) | накладные, вес, вагоны/контейнеры — по договору с РЖД и ЭЦП |
| вторая | `cn_single_window` | Единое окно КНР (单一窗口) | данные 报关单 — через ключ-носитель (UKey) импортёра или брокера |
| вторая | `kingdee` | Kingdee 金蝶云星空 | закупки и приёмка у китайской стороны (протокол уточнить у владельца) |
| вторая | `yonyou` | Yonyou 用友 YonBIP | то же (протокол уточнить у владельца) |
| вторая | `bank_fx_control` | Банк: валютный контроль | УНК, ведомость банковского контроля, поступления |

Уведомления: `wecom` (бот группы 企业微信), `telegram` (бот), `email` (SMTP).
События: `run_done` — прогон завершён, `issues_found` — найдены расхождения,
`connector_error` — ошибка коннектора. Отчёты Excel/PDF прикладываются (`send_files: true`).

## Как включить, когда появится доступ

1. Кнопка «Проверить» у коннектора второй очереди отвечает «Задел: нужен доступ — …»
   и называет, что и у кого получить.
2. Когда доступ выдан: заполните поля коннектора в `config/system.yaml`, укажите
   **имена переменных** с паролями (ниже) и нажмите «Проверить». Ответ «доступ есть» —
   ставьте `enabled: true` и перезапустите сервис.
3. Пока прямого доступа нет, у ЭТРАН, Единого окна и банка можно указать `export_dir` —
   папку, куда сохраняются выгрузки; файлы 报关单 от брокера можно забирать почтой или по SFTP.

## Пароли и ключи

В YAML пароли **не пишутся**. Пишется имя переменной окружения:
`password_env: SIBDOC_IMAP_PASSWORD`, `key_env: SIBDOC_WECOM_KEY` (или `${ИМЯ}` внутри строки).
Значения задаются на сервере: файл `.env` рядом с `docker-compose.yml` (в git не попадает),
секреты Docker или переменные службы. Если пароль всё же записан в YAML, интерфейс покажет
предупреждение, но значение не выдаст ни в интерфейс, ни в журнал.

Для SFTP сначала добавьте ключ сервера: `ssh-keyscan -p 22 host >> known_hosts` (отпечаток
сверьте с администратором) или укажите `host_key_sha256`. Опция `insecure_accept_new_host: true`
— только для первой настройки.

## В какой слот попадает файл

По `slot_rules` (регулярное выражение по имени файла, для почты — ещё и по отправителю) или
по началу имени файла (`slots`). Примеры правил по умолчанию: `报关单|customs.?dec|cn_dec` →
`cn_dec`; `ДТ|ESADout|gtd|ru_dt` → `ru_dt`. Уже забранные письма и вложения хранятся в
`storage/connectors/<id>.seen.json` — чтобы перечитать всё заново, удалите этот файл.

Каждая проверка, забор данных, ошибка коннектора и отправка уведомления записываются
в журнал без секретов.
