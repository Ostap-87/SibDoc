# История изменений

## 3.0.0-dev

### 3.0.0-dev — закрытый контур

SibDoc 3 по умолчанию работает без интернета (`docs/OFFLINE.md`).

- Единая проверка исходящих обращений `app/netguard.py`: закрытый контур (`config/system.yaml → offline`,
  `SIBDOC_OFFLINE=0|1`, по умолчанию включён) пропускает только адреса из `offline.allow_hosts`
  (имена, маски `*.corp.local`, подсети CIDR; без DNS). Через неё идут курсы ЦБ РФ и CFETS, все коннекторы
  (REST, SAP, 1С, Kingdee, Yonyou, IMAP, SFTP, БД — и редиректы, и следующие страницы API) и уведомления
  (WeCom, Telegram, SMTP). Отказ — сразу, понятной ошибкой по-русски, без ожидания таймаута.
- Курсы из файлов (флешка): ЦБ РФ XML_daily и XML_dynamic, CFETS 中间价 (Excel/CSV), шаблон Excel
  «дата, валюта, курс, источник» (`app/rates/files.py`, `POST /api/rates/import`, `GET /api/rates/template`,
  блок «Курсы из файла» в интерфейсе). Курсы попадают в кэш как официальные; выходные внутри периода файла
  заполняются последним курсом; журнал «Курсы: загрузка из файла». Ручные курсы — как раньше.
- «Обновление с носителя» (`app/media_update.py`, `POST /api/offline/update`, `tools/make_update_package.py`):
  архив справочников, правил и курсов с обязательным `SHA256SUMS` и необязательной подписью Ed25519;
  проверка до установки, копия прежних файлов, откат при ошибке, журнал «Обновление с носителя».
- Комплект для установки без интернета: `tools/make_offline_bundle.py` (+ `.sh`, `.bat`, `.command`) —
  wheelhouse для выбранных платформ и версий Python, Tesseract (Windows / Mac / Linux), установщики
  Python, образ Docker (`docker save`), шрифты, `SHA256SUMS`, `--dry-run`, `--check`. Установщики
  `install.sh`, `install.bat`, `install_mac.command`, `install_ocr_mac.command` принимают `--offline <папка>`
  (`pip install --no-index --find-links`, `docker load` вместо `docker build`).
- Интерфейс: плашка «Закрытый контур: интернет не используется» / «Есть доступ в интернет», кнопки
  «Скачать курс» в контуре выключены (`webui/offline.js`). Тест: в `webui/` нет внешних ресурсов.
- PDF: шрифт DejaVu Sans в комплекте программы (`assets/fonts/`), китайский — `assets/fonts/cjk.ttc`
  из комплекта или системный.
- Тесты: `tests/test_offline.py` (49); старые тесты работают с выключенным контуром (`tests/conftest.py`).

## 3.0.0-dev — реальное время и пакетная загрузка

Второй режим SibDoc 3 — проверка ближайшей отгрузки до подачи декларации (подробно — `docs/REALTIME.md`).

### Пакетная загрузка (`app/intake/`)
- Один запрос — сколько угодно файлов: ZIP (вложенные папки и архивы, имена в cp866), PDF (текстовый слой
  или OCR постранично), Excel .xlsx/.xls/CSV (несколько листов, GBK / Windows-1251), Word .docx (без новых
  библиотек), .doc/.rtf/.odt/.ods через установленный LibreOffice, картинки JPG/PNG/TIFF (многостраничный),
  XML, TXT, HTML, письма EML с вложениями. Неизвестный формат — «не распознан», пакет не падает.
- PDF / TIFF / книга Excel из нескольких документов делятся по страницам (заголовок другого типа или другой
  номер документа).
- Классификация без сети по правилам `config/intake/classify.yaml`: 12 типов (ДТ РФ, 报关单, черновик,
  инвойс, упаковочный лист, транспорт, сертификат, контракт, выгрузка SAP/1С, выписка банка, справочник,
  прочее), баллы, уверенность и причины; тип правится вручную, поля извлекаются заново.
- Поля единого словаря и товарные строки с источником (файл, страница / лист, строка, способ) и уверенностью
  (OCR — по строке Tesseract); реестр подключаемых разборщиков по типу документа
  (`register_extractor`) — для веток пакета ВЭД и коннекторов.
- Пакет `storage/packages/<id>/` (режим «ретро» / «реальное время», оригиналы, картинки страниц, JSON), Excel
  «Пакет.xlsx»: «Документы», лист на тип, «Требует проверки», «Источники полей».
- Tesseract в пакетной обработке — один поток на страницу (`OMP_THREAD_LIMIT=1`): при параллельной работе
  распознавание не замедляется в десятки раз.

### Проверка отгрузки (`app/realtime/`)
- Декларация со скана (ДТ РФ или 报关单) ↔ черновик ↔ система (выгрузка SAP / 1С из пакета или данные
  ретро-слотов) ↔ справочники (`references/`, справочники и контракты пакета) ↔ БД (коннектор database):
  поле за полем и строка за строкой, OK / REVIEW / ISSUE, причины по-русски и по-китайски.
- Используется логика проверок «1. Price», «2. HS code», «3. Incoterms», «4. Decl. elements» и
  `contract_match`; правила — `config/rules/realtime.yaml`; результат — JSON и «Проверка отгрузки.xlsx».

### API и ретро-режим
- `app/api_intake.py` (подключён в `app/server.py` одной строкой): `/api/intake/*` (пакеты, документы, тип
  вручную, Excel, картинки страниц, оригиналы, прогресс фоновой обработки), `/api/realtime/*`.
- «Добавить в сверку»: ДТ, 报关单, выгрузки SAP и черновики пакета — в слоты `ru_dt`, `cn_dec`, `purchase`,
  `cd_drafts`.

### Демо и тесты
- `tools/make_demo_package.py` → `data/demo/package/` — 26 документов разных форматов (вымышленные данные);
  точность классификации 26 из 26; проверка отгрузки: 36 строк — OK 29, REVIEW 1, ISSUE 6 (все заложенные
  расхождения найдены).
- Тесты: 171 → 213 (`tests/test_intake.py`, `tests/test_realtime.py`). Эталонные числа проверок ретро-режима
  не изменились (`verify.sh`).

## 3.0.0-dev — пакет ВЭД (ветка 2.1, перенесена в SibDoc 3)

SibDoc сверяет весь пакет документов отгрузки, а не только декларации.

### Данные
- Новые слоты (`config/system.yaml`, блок «ВЭД-пакет»): `invoice` — коммерческий инвойс,
  `packing` — упаковочный лист, `transport` — транспортный документ (CMR, коносамент B/L,
  накладная СМГС, авианакладная AWB; поле `doc_type`), `conformity` — сертификаты и декларации
  соответствия ЕАЭС, сертификаты происхождения (СТ-1, Form A, Form E, CO): вид, номер, даты выдачи
  и окончания действия, товар, код ТН ВЭД, страна происхождения.
- Чтение документов (`app/services/package_docs.py`): Excel/CSV — строка на позицию; шапка
  документа повторяется в колонках или стоит блоком над таблицей («Invoice No: …», «Дата | …»,
  «№ … от 10.09.2026»); строка «Итого / Total / 合计» — итоги документа; веса в тоннах
  («Брутто, т», «(MT)», «吨») переводятся в кг; выбирается лист, похожий на документ слота.
  PDF с текстовым слоем и сканы — через тот же OCR, что у деклараций; паттерны —
  `config/scan_fields.yaml → package` (без влияния на разбор деклараций). ZIP с PDF — тоже.
- Словарь полей: 21 новое поле (№ инвойса / 发票号, места / 件数, пломба / 封号, № сертификата,
  «действителен до», продавец, покупатель…) и блок `extra_synonyms` — синонимы к прежним полям
  (Net / Gross, B/L No / CMR No / № накладной → `bill_of_lading`, Shipper / Грузоотправитель,
  Country of origin / 原产地 и др.).
- ДТ XML: все документы графы 44 — в поле `presented_docs` («код номер; …»); по ним проверка
  находит ссылки ДТ на инвойс, накладную и сертификаты.
- Блок «Сканы»: вид документа определяется по заголовку (или выбирается), «В сверку» кладёт
  инвойсы, упаковочные листы, накладные и сертификаты в их слоты; в Excel предпросмотра — свои листы.

### Проверка «7. Пакет документов» (`docs_package`, правила `config/rules/docs_package.yaml`)
Отгрузка = документы с общим номером инвойса и/или контейнерами (`group_by`); при повторном
контейнере — отгрузка с ближайшей датой (`container_match_days`). Уровни: комплект
(`required_docs` → ISSUE, `expected_docs` → REVIEW); инвойс ↔ упаковочный лист (позиции,
количество, нетто, брутто, места); инвойс ↔ ДТ и ↔ 报关单 (номер инвойса среди документов
декларации, сумма и валюта — курс только при разных валютах, условия поставки); упаковочный лист ↔
транспортный документ (места, брутто с допуском %, контейнеры, пломбы); транспортный документ ↔
ДТ / 报关单 (номер в гр. 44 и 提运单号); сертификаты (действует на дату ДТ, код по началу кода
`hs_prefix_len`, марка, страна в сертификате происхождения против ДТ / 报关单). Пояснения —
`detail` (RU) и `detail_zh` (ZH). Без документов пакета — одна строка SKIPPED, прежние проверки
и эталонные числа не меняются.

### Демо-набор (`data/demo/package/`, вымышленные данные)
6 отгрузок (по одной на демо-ДТ): инвойсы Excel (шапка блоком), PDF и CSV; реестр упаковочных
листов; накладные СМГС/CMR таблицей и коносамент PDF; реестр сертификатов. Проверка находит
37 строк: 28 OK / 7 ISSUE / 2 REVIEW — брутто накладной ≠ упаковочному листу (…0002), сумма
инвойса ≠ 报关单 (…0002, цена в 报关单 ниже), страна KZ в сертификате происхождения (…0003),
нет упаковочного листа (…0004), стоимость ДТ больше инвойса (…0004, в ДТ завышен вес), истёк
сертификат соответствия (…0005), сумма инвойса ≠ ДТ (…0006); REVIEW — USD/CNY сверено через курс
(…0003) и нет 报关单 (…0006). В ДТ демо-набора добавлены документы гр. 44, в 报关单 —
提运单号 = номер накладной; результаты прежних проверок на демо не изменились.

### Отчёты и интерфейс
- Excel: лист «7 Пакет документов» и листы документов «Инвойсы 商业发票», «Уп. листы 装箱单»,
  «Трансп. документы 运输单据», «Сертификаты 证书» с двуязычными заголовками; курс пересчёта — на «Курсы».
- PDF: раздел «Пакет документов ВЭД по отгрузкам / 外贸单证包» — комплект по отгрузкам и основные
  поля документов; отклонения — в разделе проверки.
- Интерфейс: группа слотов «Пакет документов ВЭД» (принимает PDF и сканы), карточки документов
  (вкладки «Инвойсы / Упаковочные листы / Транспортные документы / Сертификаты»), выбор вида
  документа в блоке «Сканы». API: `GET /api/package-docs/{slot}`, `POST /api/scans/upload?kind=`.
- CLI: `--invoice`, `--packing`, `--transport`, `--conformity`; `verify.sh` проверяет и пакет.
- Автотесты: 171 → 206 (`tests/test_docs_package.py`: чтение документов, каждая ветка проверки, отчёты, API, сканы).

## 2.0 — 22.10.2026

По итогам аудита: все проверки считают корректно, российская ДТ и китайская декларация
стали полноценными источниками, добавлены сквозная сверка, курсы валют, журнал событий,
коннекторы РФ–Китай и двуязычные отчёты. Вход по-прежнему выключен (прототип).

### Данные
- Единый словарь полей RU / EN / ZH (`config/fields.yaml`): колонки и теги XML с разными
  названиями переименовываются автоматически.
- Загрузка: CSV в UTF-8 / Windows-1251 / GBK с разделителем `,` `;` табуляцией; Excel —
  выбор листа и строки заголовков; `.xls`; XML ДТ ФТС (ESADout_CU) и 报关单 (DecMessage);
  ZIP; несколько файлов в слот; предел размера файла.
- Новые слоты `ru_dt` и `cn_dec`, карточки деклараций в интерфейсе, листы в отчётах.
- Хранение загрузок по папкам слотов: замена файла больше не «воскрешает» старый после перезапуска.

### Курсы валют
ЦБ РФ и центральный курс НБК (CFETS) на дату документа, кэш, ручные курсы на дату или
месяц (в т. ч. месячный курс таможни КНР), режимы `official` / `manual_override`.

### Журнал
Все события, включая правки правил с разницей «было → стало», историю версий правил и
откат; фильтр по виду события; выгрузка в CSV.

### Отчёты
Номер прогона и история; Excel с листами «ДТ РФ», «报关单 КНР», «Курсы», двуязычные
заголовки, защита от формул; PDF с иероглифами и декларациями целиком.

### Коннекторы и уведомления
Почта (IMAP), папка, SFTP (проверка ключа сервера), REST, БД, SAP OData v2/v4; задел:
1С, ЭТРАН, Единое окно КНР, Kingdee, Yonyou, банк. Уведомления: WeCom, Telegram, почта.
Пароли — только переменными окружения. См. `docs/CONNECTORS.md`.

### Прочее
- OCR: текстовый слой PDF, все страницы TIFF, номер ДТ РФ, исправление «ECA» → FCA,
  распознанные сканы можно добавить в сверку.
- Безопасность: правила меняет только администратор (при включённом входе), только
  существующие файлы правил; сессии отзываются при удалении пользователя и смене пароля;
  пароль не короче 8 символов; CORS из настроек; Docker не от root.
- Автотесты (`pytest`, 164 теста), `verify.sh` проверяет все проверки и демо-набор.
